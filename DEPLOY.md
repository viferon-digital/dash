# Как развернуть главную на viferon.digital

Пошагово, от пустого места до работающего каталога на своём домене. Сборки нет,
зависимостей в рантайме нет: Cloudflare раздаёт `public/` как статику, а папка
`functions/` превращается в прослойку.

Порядок такой:

1. таблицы в Google — реестр проектов и список доступа;
2. проект Cloudflare Pages;
3. переменные и секреты;
4. вход через Google (по желанию, но лучше сразу);
5. домен `viferon.digital`;
6. проверка.

## Что должно быть под рукой

* доступ к репозиторию `viferon-digital/dash`;
* аккаунт Cloudflare, где лежит домен `viferon.digital`;
* Google-аккаунт, из-под которого создаются таблицы;
* для входа через Google и закрытой таблицы доступа — проект в
  [Google Cloud Console](https://console.cloud.google.com/) (бесплатно).

## Шаг 1. Таблица реестра

1. Создайте таблицу, назовите лист **`Проекты`**.
2. Первая строка — заголовки. Достаточно скопировать:

   ```
   Слаг | Название | Описание | Ссылка | Категория | Иконка | Статус | Порядок | Доступ | Теги | Владелец | Репозиторий | Встраивание | Обновлён
   ```

3. Заполните первые строки — например, действующие дашборды:

   | Слаг | Название | Ссылка | Категория | Иконка | Статус | Доступ | Встраивание |
   |---|---|---|---|---|---|---|---|
   | `reviews` | Отзывы о Виферон | `https://reviews.viferon.digital` | Маркетинг | 💬 | работает | все | да |
   | `uptime` | Мониторинг доступности | `https://uptime.viferon.digital` | Инфраструктура | 🛰️ | работает | admin | да |

4. **Доступ → «Любой, у кого есть ссылка — читатель»**. Публиковать в веб
   отдельно не нужно: gviz работает по этому же доступу.
5. Из адреса таблицы возьмите id — то, что между `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/`**`1AbC…xyz`**`/edit`.

## Шаг 2. Таблица доступа

Заводится **отдельной таблицей**, и вот почему: реестр открыт по ссылке, а
список людей открывать по ссылке нельзя — вместе с ним утекут хэши паролей.

1. Создайте вторую таблицу, лист **`Доступ`**, заголовки:

   ```
   Имя | Email | Пароль | Роль | Проекты | Активен | Комментарий
   ```

2. Добавьте себя: имя, рабочая почта, роль `admin`, «Проекты» — `все`,
   «Активен» — `да`. Колонку «Пароль» можно оставить пустой, если вход будет
   через Google.
3. Если пароль нужен, сделайте хэш и вставьте его целиком:

   ```bash
   npm install
   npm run hash -- 'длинный-пароль-который-не-жалко-набирать'
   # pbkdf2$sha256$210000$…$…
   ```

   Открытый пароль в таблицу не пишем никогда.
4. Доступ к таблице — **никакой ссылки**. Дальше, на шаге 5, к ней получит
   доступ сервисный аккаунт.

## Шаг 3. Проект Cloudflare Pages

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → вкладка **Pages** →
   **Connect to Git**.
2. Выберите репозиторий `viferon-digital/dash`, ветка `main`.
3. Настройки сборки:
   * **Framework preset** — `None`;
   * **Build command** — пусто;
   * **Build output directory** — `public`.
4. **Save and Deploy**. Первый деплой соберётся за минуту и даст технический
   адрес вида `viferon-dash.pages.dev`.

Пока переменных нет, сайт покажет страницу входа и не пустит дальше — так и
должно быть.

## Шаг 4. Переменные и секреты

Pages → ваш проект → **Settings** → **Variables and Secrets**, окружение
**Production** (и **Preview**, если превью-ветками пользуетесь).

Обычные переменные:

| Имя | Значение |
|---|---|
| `SHEET_ID` | id таблицы реестра из шага 1 |
| `ACCESS_SHEET_ID` | id таблицы доступа из шага 2 |
| `PROJECTS_SHEET` | `Проекты` |
| `ACCESS_SHEET` | `Доступ` |
| `CACHE_TTL` | `300` |
| `SESSION_TTL_HOURS` | `12` |
| `AUTH_MODE` | `sheet` |

Секреты (тип **Secret**, значение потом не показывается):

| Имя | Значение |
|---|---|
| `SESSION_SECRET` | длинная случайная строка: `node -e "console.log(crypto.randomBytes(32).toString('base64url'))"` |

После сохранения — **Deployments** → у последнего деплоя **Retry deployment**:
переменные подхватываются только новым запуском.

## Шаг 5. Сервисный аккаунт для таблицы доступа

Чтобы прослойка читала закрытую таблицу.

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект
   (или возьмите существующий).
2. **APIs & Services** → **Library** → включите **Google Sheets API**.
3. **APIs & Services** → **Credentials** → **Create credentials** →
   **Service account**. Имя, например, `dash-reader`. Роли не нужны — жмите
   «Done».
4. Откройте созданный аккаунт → **Keys** → **Add key** → **Create new key** →
   **JSON**. Скачается файл.
5. Из файла нужны два поля: `client_email` и `private_key`.
6. Откройте **таблицу доступа** → «Поделиться» → добавьте `client_email` с
   правом **Читатель**.
7. В Pages добавьте два секрета:

   | Имя | Значение |
   |---|---|
   | `GOOGLE_SA_EMAIL` | `client_email` из JSON |
   | `GOOGLE_SA_KEY` | `private_key` из JSON — целиком, вместе с `-----BEGIN PRIVATE KEY-----`; переводы строк можно оставить как `\n` |

8. Retry deployment.

Без этого шага всё работает, но таблицу доступа придётся открыть по ссылке —
чего делать не стоит.

## Шаг 6. Вход через Google

1. Google Cloud Console → **APIs & Services** → **OAuth consent screen**. Тип
   **Internal**, если домен в Google Workspace, иначе **External**. Заполните
   название и почту поддержки.
2. **Credentials** → **Create credentials** → **OAuth client ID** →
   **Web application**.
3. **Authorized JavaScript origins** — добавьте:
   * `https://viferon.digital`
   * `https://viferon-dash.pages.dev` (технический адрес, удобно для проверки)
   * `http://localhost:8788` (для локальной разработки)
4. Redirect URI не нужен: используется One Tap / кнопка, а не редиректный поток.
5. Скопируйте **Client ID** и положите его в Pages переменной
   `GOOGLE_CLIENT_ID` (это не секрет, он и так уходит в браузер).
6. Retry deployment — на странице входа появится кнопка Google.

Почта, которой человек входит через Google, должна быть в листе «Доступ».
Иначе он увидит понятное «для вас доступ не открыт», а не «неверный пароль».

## Шаг 7. Домен viferon.digital

1. Pages → проект → **Custom domains** → **Set up a domain**.
2. Введите `viferon.digital`. Если домен уже в этом аккаунте Cloudflare, запись
   создастся сама (apex работает через CNAME flattening).
3. Добавьте вторым доменом `www.viferon.digital` — Cloudflare сам сделает
   редирект на основной.
4. Сертификат выпускается за несколько минут; до этого возможна ошибка TLS —
   это нормально.

Дашборды удобно держать соседними поддоменами того же аккаунта:
`reviews.viferon.digital`, `uptime.viferon.digital`. Тогда ссылки в реестре
короткие, а «Открыть здесь» работает без настроек.

## Шаг 8. Проверка

1. Откройте `https://viferon.digital` — должно перебросить на `/login`.
2. Войдите (паролем или Google). Каталог показывает проекты из таблицы.
3. Допишите в таблицу тестовую строку → на главной «Обновить» → плитка на месте.
4. Уберите строку → «Обновить» → плитка исчезла.
5. Проверьте права: заведите себе роль не `admin` и «Проекты» с одним слагом —
   в каталоге должен остаться один дашборд.
6. Выйдите кнопкой ⏻ — снова страница входа.

Полезно посмотреть заголовки ответа:

```bash
curl -sI https://viferon.digital/api/projects | grep -i 'x-cache\|x-data-source'
```

## Как обновлять дальше

Пуш в `main` → Cloudflare сам собирает и выкладывает. Каталог проектов при этом
трогать не нужно: он в таблице.

Обновить резервный снапшот в репозитории:

```bash
npm run snapshot
git commit -am 'Снапшот реестра'
```

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| «Каталог пуст», хотя строки в таблице есть | не задан `SHEET_ID`, или таблица не открыта «по ссылке», или лист называется не `Проекты` |
| Баннер «показан снапшот из репозитория» | прослойка не смогла прочитать таблицу — текст ошибки там же, в скобках |
| Баннер «Google Таблица не отвечает» | Google временно недоступен; показан последний удачный список, ничего делать не нужно |
| «Сервер не настроен: не задан SESSION_SECRET» | добавьте секрет и сделайте Retry deployment |
| «Неверная почта или пароль» с правильным паролем | в колонке «Пароль» открытый текст вместо хэша, либо «Активен» = `нет` |
| «Список доступа недоступен» | таблица доступа закрыта, а сервисный аккаунт не настроен или не добавлен в «Поделиться» |
| Кнопки Google нет | не задан `GOOGLE_CLIENT_ID` или не сделан Retry deployment |
| Google-вход ругается на origin | домен не добавлен в **Authorized JavaScript origins** |
| «Открыть здесь» показывает пустой прямоугольник | дашборд запрещает встраивание своими заголовками (`X-Frame-Options`) или закрыт Cloudflare Access — тогда уберите «да» в колонке «Встраивание» |
| Всех разлогинило | сменился `SESSION_SECRET` — это ожидаемо |

## Дополнительный контур защиты (по желанию)

Список доступа закрывает сайт на уровне приложения. Если хочется, чтобы до
приложения вообще не доходили чужие запросы, поверх ставится **Cloudflare
Access** (Zero Trust → Access → Applications): домен закрывается на уровне
периметра, вход по корпоративной почте с одноразовым кодом. Одно другому не
мешает: Access решает, кто дойдёт до сайта, таблица — кто что увидит.

Учтите, что Access, поставленный на поддомены дашбордов, ломает встраивание в
iframe — колонку «Встраивание» тогда лучше оставить пустой.
