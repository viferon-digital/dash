# Главная viferon.digital — каталог дашбордов

Одна страница, с которой начинаются все остальные. Список проектов лежит не в
коде, а в Google Таблице: дописали строку — плитка появилась на главной, деплой
не нужен. Вход закрыт списком доступа из той же таблицы.

**Живая цепочка данных:** Google Таблица → Cloudflare Pages Function
(`/api/projects`) → браузер.

Архитектура та же, что у дашбордов проекта ([отзывы][reviews],
[мониторинг][uptime]): статика без сборки и без библиотек, тонкая прослойка на
Cloudflare, данные — из таблицы.

[reviews]: https://github.com/vitalijgrom/Protect-1
[uptime]: https://github.com/vitalijgrom/project-3

## Что на странице

| Блок | Что отвечает |
|---|---|
| KPI-строка | сколько всего дашбордов, сколько работают, сколько в разработке, сколько категорий |
| Фильтры | поиск по названию, описанию, тегам и адресу; категория; статус; «только закреплённые» |
| Каталог | плитки по категориям: иконка, название, домен, описание, статус, теги, кто ведёт, когда обновлён |
| Закладки | звёздочка на плитке поднимает проект в блок «Закреплённые» (хранится в браузере) |
| Просмотр | дашборд с разрешённым встраиванием открывается прямо на главной, без ухода со страницы |

Страница подхватывает тему системы, имеет переключатель светлая/тёмная и раз в
5 минут тихо перечитывает список.

## Как добавить проект

Это главный сценарий, и код в нём не участвует.

1. Откройте таблицу реестра, лист **«Проекты»**.
2. Допишите строку. Обязательны только **Название** и **Ссылка**.
3. Нажмите на главной «Обновить» — плитка на месте.

Само по себе, без кнопки, изменение доедет за `CACHE_TTL` (по умолчанию
5 минут): столько живёт кэш прослойки.

### Колонки листа «Проекты»

| Колонка | Обязательна | Что делает | Если пусто |
|---|---|---|---|
| Слаг | нет | идентификатор проекта: закладки, права доступа | делается из названия |
| Название | **да** | заголовок плитки | строка пропускается |
| Описание | нет | текст под заголовком | плитка без описания |
| Ссылка | **да** | куда ведёт плитка (`https://…`) | строка пропускается |
| Категория | нет | заголовок блока, в который попадёт плитка | «Дашборды» |
| Иконка | нет | эмодзи в квадрате слева | 📊 |
| Статус | нет | `работает` / `в разработке` / `приостановлен` | «работает» |
| Порядок | нет | сортировка внутри каталога | по порядку строк |
| Доступ | нет | кому видна плитка: `все`, роль (`admin`) или почта | всем, кто вошёл |
| Теги | нет | через запятую, участвуют в поиске | без тегов |
| Владелец | нет | кто ведёт проект | не показывается |
| Репозиторий | нет | ссылка «Исходники» в подвале плитки | не показывается |
| Встраивание | нет | `да` — появляется кнопка «Открыть здесь» | только новая вкладка |
| Обновлён | нет | дата в подвале плитки | не показывается |

Колонки ищутся по подстроке в заголовке, а не по позиции: «Ссылка», «Ссылка на
дашборд» и «URL» — одно и то же. Порядок колонок можно менять. Если заголовок
совсем не распознан, берётся позиция колонки из таблицы выше.

Строка без названия или без ссылки молча пропускается — так черновики в
таблице не ломают главную.

### Без таблицы

Каталог можно вести прямо в репозитории: те же поля объектами в
`public/data/projects.json` (образец — `public/data/projects.example.json`).
Этот файл заодно резерв: его показывает главная, если Google недоступен.
Обновить резерв из таблицы — `npm run snapshot`.

## Аутентификация

Пускать посторонних на внутренние дашборды нельзя, а заводить учётки, LDAP и
почтовые рассылки ради десяти человек — дорого. Поэтому список людей живёт там
же, где и всё остальное: в Google Таблице, лист **«Доступ»**.

**Кто есть кто.** Google (или пароль) отвечает на вопрос «кто это». Таблица
отвечает на вопрос «пускать ли и куда». Это разные вопросы, и разводить их
полезно: человек может сменить пароль, потерять доступ к почте, уволиться —
меняется одна ячейка в таблице.

### Два способа войти

| Способ | Как проверяется | Когда удобен |
|---|---|---|
| **Google** | браузер получает от Google подписанный ID-токен, прослойка проверяет подпись ключами Google, издателя, срок и то, что токен выписан нашему приложению; затем ищет почту в листе «Доступ» | у всех рабочие Google-аккаунты — пароль заводить не нужно |
| **Почта и пароль** | PBKDF2-хэш из колонки «Пароль» сверяется с введённым | подрядчику или общей учётке, у которых нет нашего Google |

Оба заканчиваются одинаково: подписанной кукой сессии.

### Колонки листа «Доступ»

| Колонка | Что в ней |
|---|---|
| Имя | как показывать человека в шапке |
| Email | ключ: по нему ищут и Google-вход, и вход по паролю |
| Пароль | хэш `pbkdf2$sha256$…` (делает `npm run hash`). Пусто — вход только через Google |
| Роль | `admin` видит всё; любая другая роль работает как метка для колонки «Доступ» реестра |
| Проекты | что открыто: `все` / `*` или список слагов через запятую |
| Активен | `нет` — вход закрыт, строку можно не удалять |
| Комментарий | для людей, код его не читает |

### Как считается доступ к проекту

Право должно сойтись с двух сторон:

* в реестре у проекта колонка **«Доступ»** — кому он виден;
* в листе доступа у человека колонка **«Проекты»** — что ему открыто.

Пересечение и есть то, что человек видит на главной. Роль `admin` проходит без
проверок. Фильтрация делается на сервере: в браузер чужие проекты не уезжают
даже скрытыми.

### Сессия

Подписанная кука `vd_session`: `HttpOnly` (JavaScript её не прочитает),
`Secure` (по HTTP не уйдёт), `SameSite=Lax` (к чужим POST-ам не приложится),
подпись HMAC-SHA256 на `SESSION_SECRET`. Состояния на сервере нет — в куке
лежит почта, роль, список проектов и срок; подделать это, не зная секрета,
нельзя. Срок — `SESSION_TTL_HOURS` (по умолчанию 12 часов), дальше нужен
повторный вход.

Смена `SESSION_SECRET` мгновенно разлогинивает всех — это и есть «кнопка
паники».

### Где хранить лист доступа

Таблица реестра открыта «по ссылке — читатель»: gviz иначе не работает, а
секретов в списке дашбордов нет.

**Лист доступа так открывать нельзя.** Если таблица читается по ссылке, её
читают все, кому эта ссылка попалась, — вместе с хэшами паролей. Правильно:
отдельная таблица, доступ только у сервисного аккаунта Google
(`GOOGLE_SA_EMAIL` + `GOOGLE_SA_KEY`), у неё же `ACCESS_SHEET_ID`. Прослойка
ходит в неё по Sheets API v4, а не по ссылке.

Если сервисного аккаунта нет, схема всё равно работает через gviz, но тогда:
пароли обязаны быть хэшами (не открытым текстом), а ссылку на таблицу нельзя
давать никому, кроме администраторов. Открытый текст в колонке «Пароль»
разрешается только флагом `ALLOW_PLAINTEXT=1` — это отладочный режим, в проде
его быть не должно.

### Ограничение перебора

Восемь неудачных попыток на связку «почта + IP» — и на 15 минут вход по паролю
для неё закрыт. Счётчик живёт в памяти воркера, поэтому от распределённого
перебора он не спасает; если понадобится настоящий предел, ставится правило
Cloudflare WAF на `/api/auth/*`. Ответ на неверный вход всегда один и тот же
(«неверная почта или пароль») — иначе перебором собирается список сотрудников.

## Структура

```
public/
  index.html                 каталог
  login.html                 вход
  assets/styles.css          токены светлой и тёмной темы, компоненты
  assets/theme.js            тема до первой отрисовки (отдельным файлом ради CSP)
  assets/app.js              загрузка, фильтры, плитки, встроенный просмотр
  assets/login.js            форма входа и кнопка Google
  data/projects.json         снапшот реестра на случай недоступности прослойки
  data/projects.example.json образец полей
functions/
  _middleware.js             ворота: сессия, редиректы, заголовки безопасности
  api/projects.js            реестр: Google Таблица → JSON, фильтр по доступу
  api/auth/login.js          вход по паролю
  api/auth/google.js         вход по Google ID-токену
  api/auth/logout.js         выход
  api/auth/me.js             кто вошёл и какие способы входа включены
  lib/sheets.js              чтение таблиц: gviz и Sheets API v4
  lib/registry.js            разбор листа «Проекты»
  lib/access.js              разбор листа «Доступ», пароли, права
  lib/google.js              проверка ID-токена Google
  lib/session.js             подписанные куки
scripts/
  snapshot.mjs               обновление снапшота из таблицы
  hash-password.mjs          хэш пароля для листа доступа
wrangler.toml                конфиг Pages: каталог сборки и переменные
```

## Прослойка

`GET /api/projects` — реестр, из которого вырезано всё, к чему у вошедшего нет
доступа. `GET /api/projects?refresh=1` — то же мимо кэша (кнопка «Обновить»).

Кэшируется не ответ, а сам реестр: ответ у каждого свой. Полный список лежит в
edge-кэше Cloudflare под внутренним ключом (`CACHE_TTL`, по умолчанию 300
секунд), наружу уходит `cache-control: no-store`. Отдельно хранится последний
удачно прочитанный реестр: если Google лёг, отдаётся он с `x-cache: STALE`,
а если и его нет — снапшот из репозитория. Главная не белеет ни в одном из
случаев и пишет в баннере, что показывает.

Заголовки ответа: `x-cache` (`HIT` / `MISS` / `BYPASS` / `STALE` / `SNAPSHOT`)
и `x-data-source`.

## Переменные окружения

| Переменная | Что | По умолчанию |
|---|---|---|
| `SHEET_ID` | id таблицы реестра | — (без неё показывается снапшот) |
| `PROJECTS_SHEET` | лист реестра | `Проекты` |
| `CACHE_TTL` | кэш реестра, секунды | `300` |
| `AUTH_MODE` | `sheet` — вход по списку; `off` — сайт открыт | `sheet` |
| `ACCESS_SHEET_ID` | id таблицы доступа | значение `SHEET_ID` |
| `ACCESS_SHEET` | лист доступа | `Доступ` |
| `ACCESS_TTL` | кэш списка доступа, секунды | `60` |
| `SESSION_SECRET` | **секрет**, подпись куки | — (без неё вход не работает) |
| `SESSION_TTL_HOURS` | срок сессии | `12` |
| `GOOGLE_CLIENT_ID` | OAuth-клиент; без него кнопка Google не показывается | — |
| `GOOGLE_SA_EMAIL` | **секрет**, почта сервисного аккаунта | — |
| `GOOGLE_SA_KEY` | **секрет**, приватный ключ сервисного аккаунта (PEM) | — |
| `ALLOW_PLAINTEXT` | `1` — разрешить открытые пароли в таблице (только отладка) | выключено |

## Локальный запуск

```bash
npm install
cp .dev.vars.example .dev.vars   # и вписать SHEET_ID, SESSION_SECRET
npm run dev                      # http://localhost:8788
```

Без списка доступа удобно поставить `AUTH_MODE=off` в `.dev.vars` — тогда вход
не спрашивается. В проде так делать нельзя.

Полезное:

```bash
npm run hash -- 'пароль-который-не-стыдно'   # хэш для листа «Доступ»
npm run snapshot                             # обновить public/data/projects.json
```
